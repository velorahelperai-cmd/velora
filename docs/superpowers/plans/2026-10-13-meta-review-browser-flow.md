> التنفيذ داخل هذه المحادثة، خطوة واحدة ثم تحقق؛ لا تتجاوز خطوة فاشلة. هذه خطة تشغيل وليست شهادة نجاح الربط.

**الهدف:** مساران حقيقيان محفوظان في Velora، قابلان لإعادة التجربة بواسطة مراجع ميتا، ثم أربعة فيديوهات مطابقة للصلاحيات المطلوبة.

**النطاق المعتمد:** إبقاء تطبيق ميتا منشورًا، واختبار إنستجرام بحساب المراجعة فقط. واتساب يستخدم أصول Meta الاختبارية. لا تفعيل للعملاء ولا استدعاءات AI مدفوعة.

**المنظومة:** Next.js 16.3.8، Supabase، Instagram Login، WhatsApp Cloud API. التفويض والحفظ والتحقق من الرسائل على الخادم وقاعدة البيانات؛ الواجهة تعرض الدليل الفعلي.

## بوابات التنفيذ المتسلسلة

### 1. تثبيت هوية المراجعة وحالة التشغيل

- [x] قراءة حالة شركة المراجعة وعضويتها واستحقاقها من قاعدة البيانات وإعدادات النشر، دون عرض أسرار.
- [x] تجهيز شركة المراجعة عبر مسار الإدارة المعتمد، وتنفيذ تصريح المراجعة المنفصل الذي وافق عليه المستخدم، دون دفع وهمي.
- [x] فتح الصفحتين بحساب المالك وتشخيص أخطاء OAuth والتوقيع من الأدلة الفعلية.

**النجاح:** مالك الشركة الصحيحة يستطيع فتح صندوق المحادثات؛ لا منع بسبب `setup` ولا تحميل مستمر. المستخدم غير المخول يظل ممنوعًا. عند نقص استحقاق مشروع، تتوقف تجربة الإرسال إلى أن يتوفر المسار المعتمد.

### 2. عزل اختبار واتساب في النشر الفعلي

- [x] مطابقة Test WABA وTest Phone Number والمستلم المسموح فعليًا لدى ميتا.
- [x] نشر وضع `meta_test` بأصول ورمز مستقلين، دون بديل حي عند نقص إعداد الاختبار.
- [x] إبقاء AI والعمال الآليين معطلين؛ إرسال يدوي محصور بالتصريح والأصل والمستلم ونافذة الرسالة الموقّعة.

**النجاح:** الواجهة تعرض وضع الاختبار من إعداد الخادم، والأصل الفعلي مطابق لميتا. نقص رمز/معرف الاختبار يمنع العمل ولا يستخدم الأصل الحي بدلًا منه. لا تغيير لحالة نشر تطبيق ميتا.

### 3. إثبات استقبال وإرسال واتساب

- [x] اشتراك التطبيق في Test WABA وتوقيع الوارد وربط الرقم بالشركة الصحيحة مثبتة.
- [x] الوارد من المستلم المحدد محفوظ وظاهر بعد تحديث صندوق Velora.
- [x] الرد اليدوي محفوظ؛ ميتا أعادت حالة `read`. لم يستخدم تصريح المراجعة أي إثبات دفع.

**النجاح:** نفس محتوى الرسالة ظاهر عند الطرفين، ومعرفات الأحداث محفوظة، ولا تكرار إرسال عند إعادة التحميل، ولا وصول الرسالة لشركة أخرى. إذا كانت نتيجة الإرسال غير محسومة، تُراجع قبل أي إعادة.

### 4. استكمال دليل إدارة واتساب

- [ ] فتح تعليمات الفيديو التفصيلية في صفحة تأهيل مزوّد التقنية. تنفيذ إنشاء قالب في WhatsApp Manager إذا كانت التعليمات تسمح بهذا المسار، مع إظهاره ضمن رحلة واضحة من Velora.
- [ ] إذا كانت التعليمات تشترط الإدارة داخل المنتج، بناء مسار حقيقي محدود لإنشاء/قراءة القوالب وإظهار الحالة، بتفويض مالك وحفظ وربط بالأصل الصحيح؛ بلا شاشة صورية.
- [ ] مطابقة وصف `whatsapp_business_management` بالوظائف المنفذة فعلًا؛ إثبات حساب/رقم مفوض، اشتراك Webhook، والقالب وفق المسار المقبول.

**النجاح:** القالب موجود لدى ميتا، ومسار إدارته قابل لإعادة التنفيذ، ووصف الصلاحية لا يناقض الفيديو. لا يبدأ التصوير قبل حسم التعليمات التفصيلية.

### 5. إنستجرام: ربط حقيقي قابل لتجربة المراجع

- [ ] مطابقة Instagram App وredirect URI على `www.velorahelper.com` واشتراكات الرسائل والصلاحيتين؛ لا استخدام سر تطبيق واتساب كبديل.
- [ ] تجربة زر الربط بحساب المراجعة، وتشخيص أي رفض من مرحلته الفعلية. مراجعة `owner-actions.ts` و`oauth-meta.ts` و`connect-scope.ts` ومخزن الربط.
- [ ] توفير مسار تفويض أصلي لمالك شركة المراجعة يسمح للمراجع بربط حسابه الاحترافي بنفسه، بدل اشتراط اسم `velorahelperai` عليه. يُحصر الإتاحة بالشركة/المالك/التطبيق، مع التحقق من الحساب والصلاحيات على الخادم وحفظها؛ لا قبول هوية من المتصفح ولا فتح الربط لكل الشركات.
- [ ] حفظ وعرض بيانات الحساب الحقيقية المطلوبة في الفيديو. المعرف معروض حاليًا؛ إن أضفنا اسم المستخدم، يُمرر من استجابة ميتا الموثقة إلى التخزين ثم واجهة الحالة، دون اختلاقه.

**النجاح:** OAuth يعود للشركة الصحيحة، والحساب والاشتراك محفوظان ويظهران بعد تحديث الصفحة. إلغاء التفويض أو حساب غير احترافي لا يُنتج اتصالًا ناجحًا. مسار المراجع لا يتوقف بسبب قيد اسم حسابنا أو انتهاء تصريح قصير أثناء فترة المراجعة.

### 6. إنستجرام: استقبال ثم رد يدوي

- [x] التوقيع والتوقيت ونافذة الرد والتصريح المنفصل مثبتة من الرسالة الفعلية، مع حصر الإرسال بالشركة والأصل والمرسل.
- [x] الوارد الحقيقي محفوظ وظاهر في Velora.
- [x] الرد اليدوي محفوظ وقبِلته ميتا، والمستخدم أكد وصوله لحسابه الشخصي.

**النجاح:** الرسالتان حقيقيتان ومحفوظتان. الحساب غير المخول والشركة الأخرى ونافذة الرد المغلقة ممنوعون. قبول ميتا للطلب لا يُعرض باعتباره تأكيد تسليم.

### 7. تصوير أربعة فيديوهات بعد اجتياز البوابات

- [ ] **`whatsapp_business_messaging`:** دخول Velora ← شركة المراجعة ← رقم ميتا الاختباري ← وارد يظهر في الصندوق ← رد من Velora يظهر في واتساب. تصوير الطرفين.
- [ ] **`whatsapp_business_management`:** رحلة التفويض/الأصول والرقم واشتراك Webhook، ثم إنشاء/عرض القالب وفق تعليمات التأهيل التي حُسمت في الخطوة 4. الفيديو يطابق الوصف النهائي.
- [ ] **`instagram_business_basic`:** دخول Velora ← ربط حساب احترافي عبر Instagram Login ← العودة وعرض معلومات الملف الحقيقي. توضيح أنها صلاحية لازمة للمراسلة. تعليمات المراجع تحدد مكان المعلومات وكيف يربط حسابه؛ لا مشاركة بيانات دخول Instagram.
- [ ] **`instagram_business_manage_messages`:** الحساب المرتبط ← رسالة واردة حقيقية ← عرض المحادثة ← حفظ وإرسال الرد ← ظهور الرد في Instagram عند الطرف الآخر.

**النجاح:** أربعة ملفات واضحة، شرح/تسميات بالإنجليزية، لا أسرار أو بيانات عملاء، ولا قفز فوق الربط أو استخدام رسائل وهمية. لكل فيديو وصف وتعليمات يمكن للمراجع اتباعهما.

### 8. تحقق الإصدار وإعادة التجربة

- [ ] لأي إصلاح برمجي: اختبار فشل مادي قبل الإصلاح، الاختبارات ذات الصلة بعده، ثم `npm run typecheck` و`npm run build` عند إعداد الإصدار. قراءة دليل Next.js المحلي قبل تعديل مساراته.
- [ ] بعد النشر: تجربة دخول المراجع والربط والحفظ والرسائل من المتصفح على الإصدار المنشور، والتأكد من بقاء العزل بعد إعادة الدخول.
- [ ] رفع الملفات والتحقق من حفظ كل مرفق ووصفه. إرسال طلب مراجعة التطبيق إجراء نهائي منفصل بعد اكتمال الأدلة والتعليمات.

**النجاح النهائي:** المراجع يستطيع تكرار المسارين على الموقع، والأربعة فيديوهات تمثل السلوك المنشور. تسجيل «مكتمل» في ميتا أو نجاح اختبارات محلية لا يستبدل هذا التحقق.
