# Velora Launch Readiness Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Delegation requires the user's choice. Track steps with checkboxes.

**Goal:** رحلة عميل تعمل من إنشاء الحساب حتى الاشتراك وربط واتساب والرد من معرفة الشركة، مع إثبات العزل والأمان قبل إطلاق العملاء والدفع الحقيقي.

**Architecture:** استكمال الوحدات الحالية دون إعادة بناء المنتج. إثبات الحالة أولًا ثم التحقق من كل مسار على بيئة اختبار قبل ربطه بالمسار التالي. هذه خطة إطلاق مرحلية؛ تكامل المزوّد ومخزن الأسرار وعقد العملة يحتاج كل منها مواصفة محددة بعد حسم الخيارات.

**Tech Stack:** Next.js 16.3.8، React 19.3.0، TypeScript، Supabase، Vitest، Meta WhatsApp، Paymob.

**Spec:** طلب المستخدم إعداد خطة بناءً على الوضع الحالي؛ docs/security-launch-plan-01.md، docs/access-management-01-design.md، docs/billing-dashboards-01-design.md، docs/leads-journey-01-design.md، وعقود src/lib/ops وsrc/lib/answers وsrc/lib/whatsapp وsrc/lib/billing.

## Global Constraints

- ممنوع فتح أو قراءة أو البحث أو تعديل أي شيء داخل Obsidian بما فيه Handoffs وملفات القرارات.
- قبل تعديل كود: قراءة دليل Next.js المناسب داخل node_modules/next/dist/docs؛ لا نفترض سلوك middleware/proxy من إصدار سابق.
- الحفاظ على تعديل CSS المحلي وفهم سبب حذف src/middleware.ts قبل أي إصلاح؛ وجود src/proxy.ts وحده ليس إثبات حماية تشغيلية.
- فصل PASS_LOCAL عن PASS_STAGING وعن حالة الإنتاج؛ وجود مسار كود لا يثبت تفعيله.
- إعداد الخطة لا يصرح بتطبيق هجرات سحابية أو تفعيل خدمات مدفوعة أو إرسال رسائل أو نشر. تُجهز حزمة قابلة للمراجعة قبل اعتماد تشغيل خارجي محدد.
- لا نسجل قيم الأسرار؛ نسجل وجود الإعداد ونتيجة التحقق فقط.
- إعادة استخدام الاختبارات الحالية وإضافة اختبارات للسلوك المتغير والمخاطر الفعلية فقط.

## Review Focus

1. انتهاء الجلسة: رفض الوصول المحمي دون كشف بيانات — مرحلة 1.
2. عضوية شركتين أو موظف محدود: اختيار شركة صريح وحراسة خادمية — مرحلتا 2 و3.
3. تكرار webhook واختلاف ترتيب الأحداث: لا اشتراك أو إرسال مكرر — مراحل 4 و5 و6.
4. فصل رقم واتساب وإعادة ربطه: رفض أسرار وجيل الربط القديم — مرحلة 5.
5. فشل AI أو نفاد الميزانية أو غياب المعرفة: نتيجة صادقة دون جواب مختلق أو إعادة إرسال غير محسوبة — مرحلة 6.

## ترتيب التنفيذ والمتابعة

1. تثبيت الكود والحماية → قاعدة البيانات والاختبار → رحلة العميل.
2. الدفع التجريبي → واتساب → AI → الأمان والإطلاق المحدود.
3. نجمع قرارات Meta ومزوّد AI والميزانية والعملات خلال المراحل الأولى دون تشغيل الخدمات.
4. لكل مرحلة: الحالة والدليل والعائق والخطوة التالية. لا نسبة إنجاز أو موعد نهائي قبل قياس المرحلتين الأولى والثانية.
5. إعداد هذه الخطة لم يشغّل اختبارات أو هجرات أو نشر؛ جميع المهام تنتظر دليل التنفيذ.
